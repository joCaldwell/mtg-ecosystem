# Native client integration checkpoint

This implements the first native slice of the reviewed client plans. It does not
complete M0, M1–M4, action discovery, or a human-play acceptance gate. Base source:
`691496f` (the merged planning PR #12 is an ancestor). Owned paths are game-server
Rust, its offline tools/example, and this report. No SDK/client source, hosted
profile, core semantics, public observation version or IR version changed.

## Committed resume: frozen implementation contract

Rust `protocol::SeatResume`, generated by `mtg-server schema`, is authoritative.
`get_resume` is `GET /v1/matches/{match_id}/resume`. Authentication selects the
viewer; no query parameters, body or caller-selected viewer are accepted.

| Field | Producer and interpretation |
| --- | --- |
| protocol_version | Transport version 1; schema requires exactly 1 |
| match_id, viewer | Worker identity and authenticated seat |
| engine_build_id, server_build_id, catalog_sha256 | Immutable worker bootstrap identity; no private profile digest |
| next | Canonical decimal u64, last own publication included in this read; poll strictly after it |
| state | `pending` before any committed view, otherwise `available` with the exact last permitted Observation, including its decision/token |
| lifecycle | Last committed published lifecycle status, or null when none exists; not the current private execution phase |
| outcome | Last committed published rules outcome, or null when none exists |

A single SQLite read transaction reads the seat head and three indexed latest
publication seeks. The expression index uses seat/kind/cursor; reads do not replay
history, run Game, change clocks, generate handles, or publish cursors. The latest
view survives lifecycle-only publications. Lifecycle and outcome can both be
present; outcome is authoritative for terminal display. Null does not invent a
running state. Pending must not erase a retained observation in the same client
binding. A resume response does not establish command execution disposition.

Bounds are inclusive: 65,536 bytes per persisted publication, 131,072 bytes per
resume response. Oversize/corrupt/unavailable results fail closed with generic
503, never a truncated view or a rules loss. Existing 64-request HTTP semaphore,
bounded broker, 25-second request timeout apply; dropping a read has no gameplay effect (the already queued read may still finish). Unknown/malformed inputs
and unauthenticated calls retain existing 400/401/404 mappings. Responses use
`Cache-Control: no-store`. No global operation counter, state digest, query Work,
receipt, seed or other-seat history enters the DTO.

Consumer validates protocol/match/viewer/build/catalog against the imported
bootstrap and expected session before installing state. Compatibility is explicit:
route/schema addition changes SDK generation inputs even though transport version
remains 1. Older SDK generators reject the new envelope until adapted. Host build
identity changes and existing different-build durable matches remain incompatible;
there is no live migration. The index is derived from existing publication data,
not an alternative semantic projection. SQLite documents the required exact
[expression-index match](https://www.sqlite.org/expridx.html) and stable
[read-transaction snapshot](https://www.sqlite.org/lang_transaction.html#read_transactions_versus_write_transactions); both were checked for this implementation.

## Single-seat bootstrap: frozen implementation contract

`mtg-server bootstrap-schema` exports a standalone Draft7 schema for
`SeatBootstrap`. `export-seat ROOT ID SEAT ORIGIN ISSUED_FILE OUTPUT` runs offline
under the existing exclusive registry lock, before `serve`. It selects an already
issued credential; it never rotates a seat implicitly. Initial create files and
rotated-seat files are accepted only for their matching registry/match/seat and
current capability verifier. Revoked and old rotated credentials reject.

Fields: bootstrap_version=1, protocol_version=1, server_origin, match_id, viewer,
capability, engine_build_id, server_build_id, catalog_sha256. No operator secret,
other seat capability, seed, config, catalog IR or private profile hash is exported.
Origin is the exact `http://` plus Rust SocketAddr spelling for 127.0.0.1 or [::1]
and an explicit nonzero decimal port <=65535. No hostname aliases, alternate
loopback address, userinfo, path, query or fragment is accepted. The schema's
lexical port bound is supplemented by producer SocketAddr validation; browser
import must validate the numeric port too (and account for URL default-port
normalization when comparing upstream mappings).

Output is create-new, at most 4096 bytes, mode 0600, outside the registry, under a
private same-owner directory. Existing symlink/path/file-ownership safeguards
apply. Errors never include decoded capability material. The browser imports
exactly one such file; it keeps the bearer only in memory/Authorization headers.
Issued-file input and registry stay operator-private. Static same-origin serving,
Host/Origin enforcement and proxy/CSP proof remain browser-integration gates.

## Exact command and journal semantics

Resume is a committed read, not a replacement command protocol. Preserve the
exact CommandEnvelope (ID, original expected_revision, token and response) before
sending. Durable Accepted remains unresolved Pending until command_execution says
ConsumedByRules, DiscardedByDeparture, Cancelled or Rejected. Immutable duplicate
submission outcomes precede stale-revision checks. Neither changed view/token,
transport abort, a missing execution row, nor a newer resume cursor authorizes
replacing an ambiguous command. Never retry with a fresh revision or ID under the
same unresolved intent. A 404 can coexist with an original request still arriving.
Journals survive refresh/incompatible builds, bind origin/match/seat/build/catalog,
and are scanned by origin/match/seat before changing build binding. They contain
no capability or full observation. One unresolved envelope; provisional journal
record ceiling 128 KiB (65,536-byte envelope plus bounded binding/status metadata).
Client history provisional cap: 32 observations, evict display history only, never
an unresolved journal. These client budgets require the SDK/session lane's proof.

## Offline presentation and request inventory

`tools/client-artifacts.ts` is a separate TypeScript producer, invoked explicitly
with a pinned catalog and native schema. It never starts Cargo or fetches cards.
It verifies each compiler provenance.source_json SHA256 and Oracle/printing
identity, then emits only face names, Oracle/mana/type text, stored HTTPS artwork,
face indices and source digests. Every source face is preserved (1–8); no inferred
face pairing or synthesized image lookup is allowed. Printed text is not runtime
semantics. Missing text/artwork is null. `ability_mapping: unavailable` explicitly
marks missing compiler-owned semantic labels; no runtime code guesses labels
from Oracle text or IR. Presentation is catalog-bound, not a player observation.
The first produced artifact contains 34 public catalog entries; only permitted

The producer owns `presentation.schema.json`. Consumers generate types from that

serving of this static artifact are **not implemented** in this checkpoint.

## Action/context coordination: next checkpoint, not a runtime contract

Both peers reviewed this direction. Only resume/bootstrap are schema-frozen now.
Core PlayerSession currently exposes observe, decision, check_response, resume and
search_context; action enumeration is absent. HTTP/TS must not fill that gap.

Proposed core action query binds the current token plus window or one existing
ObjectHandle scope. Beginnings carry an existing PlayerResponse initiation,
permitted source reference and an optional compiler-backed label reference.
Results distinguish complete, incomplete (host-opaque continuation), stale and
unavailable context. Null source means it is not permitted; it does not authorize
an identity lookup. A listed initiation proves only that initiation, never joint
later targets/payment/choices. Core must reuse its shared validation predicates.
Ordering must be deterministic by permitted scope/handle/ability identity, stable
within one token; no hidden-source order or hidden-derived reason is observable.

DecisionContext binds token and permitted object/stack source, optional semantic
ability/source-block/mode references and existing cost data. Compiler tooling must
supply exact source mappings before labels become available. No localized strings,
Oracle parsing or executable IR interpretation is delegated to host/UI.

Provisional investigation bounds: 64 beginnings/page, 10,000 core units/request,
64 KiB reply, one continuation/seat, 60-second host idle expiry. Continuations bind
viewer/token/core epoch; cancellation discards query work only. Incomplete work,
stale token, absent label and illegal response are distinct. No query publishes
history or becomes a clock/resource-pause/rules outcome. Before route/schema
freeze, prove budget progress, purity, cancellation and hidden-state paired cases;
freeze generated operations and per-operation bounds with the SDK lane. These
bounds/designs are not implemented APIs or acceptance evidence.

## Reproduction and evidence

Native builds use pinned `scripts/engine-env.sh`, the existing shared cargo.lock,
and the explicitly coordinated performance cache with ENGINE_CACHE_MAX_GIB=32.
No dependency installation or node_modules replacement was performed. Doctor
reported missing root Node dependencies; native and dependency-free producer checks
run without them. All retained output is under `generated/client-native/` in this
T3-bound worktree; generated artifacts/binaries/credentials remain ignored.

```sh
# Native owner only, under shared lock:
cargo test --locked -p mtg-server --lib
cargo build --locked -p mtg-server --bin mtg-server --example client_fixture
cargo clippy --locked -p mtg-server --all-targets -- -D warnings
# Explicit pinned binary, never implicit Cargo:
mtg-server schema > protocol.schema.json
mtg-server bootstrap-schema > bootstrap.schema.json
client_fixture NEW_SCRATCH NEW_OUTPUT
sh scripts/engine-env.sh node packages/game-server/tools/client-artifacts.ts \
  packages/game-engine/tests/fixtures/expected-match-ir.json \
  protocol.schema.json NEW_OUTPUT_DIRECTORY
sh scripts/engine-env.sh node --test packages/game-server/tools/client-artifacts.test.ts
```

Passed: six initial selected library tests, then 56 server library tests;
server/fixture build; all-target server Clippy with warnings denied; two offline
producer tests. Actual authenticated HTTP resume from the isolated native worker
returned viewer 0, opening mulligan, own cursor 1, 6218 bytes and no-store.
The first offline fixture run failed with a nonmonotonic clock because it reused
a pre-create timestamp; the helper now samples a fresh Instant per advance. The
failed scratch/binary and successful HTTP capture are preserved separately.
Further fixture/native HTTP checks and exact artifact hashes belong in the
checkpoint handoff below.

Omitted: engine-wide test matrix, release/performance/retention gates, arbitrary
profiles, semantic action queries, full decision coverage, natural games, human
usability, durable browser journal acceptance, four-browser privacy/recovery and
full M0 browser acceptance. SDK/browser results are independently source-qualified
by that lane; these host-only checks cannot establish actual-browser proof.
